# Live run against a real OpenID provider

Everything the test suite proves about this service uses tokens the tests mint
themselves. This lab runs the published image against a real provider,
Keycloak, with two throwaway realms and generated credentials, and walks the
loop: exchange, DPoP binding, delegation, revoke, the time to the first refusal,
ban and lift, and the tokens that must be refused.

Nothing here is a real account. Every credential is generated by `provision.sh`
under `$LAB/secrets` (mode 600) and is never printed.

## What it needs

- Docker, `curl`, `jq`, `openssl`, Go (for `vxlab` and `vouchryx-demo`).
- A host where ports `127.0.0.1:18080` (Keycloak) and `127.0.0.1:14310`
  (vouchryx) are free. Both listen on loopback only.
- Keycloak is started by hand once, in its own Docker network:

```sh
LAB=$HOME/vxlive; mkdir -p $LAB/secrets && chmod 700 $LAB/secrets
(umask 077; openssl rand -hex 16 > $LAB/secrets/kc-admin.pass)
docker network create vxlive-net
docker run -d --name vxlive-keycloak --network vxlive-net -p 127.0.0.1:18080:8080 \
  -e KC_BOOTSTRAP_ADMIN_USERNAME=admin -e KC_BOOTSTRAP_ADMIN_PASSWORD="$(cat $LAB/secrets/kc-admin.pass)" \
  -e KC_HOSTNAME=http://127.0.0.1:18080 -e KC_HTTP_ENABLED=true \
  quay.io/keycloak/keycloak:26.8.1 start-dev
```

- The two helper binaries, built from this repository:

```sh
go build -o $LAB/bin/vouchryx-demo ./cmd/vouchryx-demo
(cd labs/oidc-keycloak/vxlab && go build -o $LAB/bin/vxlab .)
```

- Two holder keys the scripts present proofs with: `vouchryx-demo keygen -out
  $LAB/holder1` (and `holder2`, `holder3`).

## Running it

```sh
cp labs/oidc-keycloak/*.sh $LAB/ && cd $LAB
./run-all.sh ghcr.io/taipanbox/vouchryx:v0.6.1   # or any image, or a local build
```

`run-all.sh` provisions both realms, then starts the service in four
configurations and runs a phase against each:

| phase | configuration | what it proves |
|---|---|---|
| 1 | the `vxlive` realm trusted, bound tokens only | exchange with real tokens; DPoP binding; hostile and wrong tokens; revoke and the time to the first refusal; ban, lift, restart with a ban in force |
| 2 | the realm unmarked, then marked `\|unbound` | a provider's bearer token is refused without the marker and exchanged with it |
| 3 | agents enrolled, a workload issuer, the service's own issuer trusted | an agent's own credential (enrolment key, and a workload token the provider issued); the hand-off; a ban reaching into the chain; revoking by `jti` |
| rotation | `VOUCHRYX_JWKS_RELOAD_SECONDS=5` | the provider rotates its key; the refresh job replaces the key set file; the service follows without a restart |

Each line is `PASS` or `FAIL`; a refusal's reason is read from the service's log,
because the response says nothing about which check failed (invariant 5).

## What the realms look like

`vxlive` is the provider the service trusts, with one user and these clients:

| client | what it is for |
|---|---|
| `vx-user` | the user's token, bound to the caller's key with DPoP |
| `vx-user-bearer` | the same, bearer (no `cnf`) |
| `vx-user-short` | a 5 second token, for the expiry case |
| `vx-user-account-aud` | a token with the default audience, not vouchryx's |
| `vx-user-es256` | a token signed with an EC key |
| `vx-agent` | a service account, DPoP-bound, the actor token |
| `vx-agent-wl` | a service account whose token is a workload assertion |

`vxother` is a second provider the service does not trust. A provider's own
`sub` is an opaque id, and this service takes a subject only as a `user://` or
`agent://` URI, so `provision.sh` tells Keycloak to write the URI into `sub` with
a hardcoded-claim mapper (see the README, "What an identity provider has to look
like").

## The two helpers

`vxlab` is the client side the service does not have: `enforce` and `watch` check
a delegation token the way a door does (the service's key set, the revocation
list it polls, the proof bound to the token's key), and `forge` damages a real
token in one named way (`none`, `hs256`, `aud`, `sub`, `exp`, `algdown`,
`ecalg`). It is its own Go module so that it stays out of the repository's test,
lint and manifest.

`evidence/` holds the output of the runs against the published `v0.6.1` image
and against the build with the key set reload.
