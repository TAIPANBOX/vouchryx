# vouchryx 0.7.0

A minor release on 0.6.1. The service now follows the key set files of its trusted and workload issuers while it runs, so a provider that rotates its signing key is trusted again without a restart. The change is on by default, and the Upgrade section says what an operator sees.

## Upgrade

- **Key set files are read again every 30 seconds.** `VOUCHRYX_JWKS_RELOAD_SECONDS` is new and defaults to 30. It is a whole number of seconds, up to one day. `0` reads the files at start only, as 0.6.1 did. Nothing else needs doing: a deployment that never rotates a key sees no difference.
- **A file that cannot be used never replaces the keys held.** An unreadable or missing file, one that is not JSON, an error page, a set with no keys, and a key with no `kty` or no `kid` are all refused with the same reading the start applies. The issuer keeps the set it has, the refusal is logged once while it lasts, and the recovery is logged once.
- **A key removed from a readable file stops verifying.** A token signed by it is refused from the next read.
- **The service still fetches nothing.** A refresh job writes the key set file and the service reads it. Fetching a provider's `jwks_uri` from here would make it an outbound caller and an availability dependency of every exchange.

Rollback is to run the 0.6.1 image again, which reads each file once at start.

Pull `ghcr.io/taipanbox/vouchryx:v0.7.0` and restart.

## Changed since 0.6.1

- **Key sets follow the files (#65).** A live run against Keycloak 26.8.1 (throwaway realms, generated credentials, one Linux host) found that a provider's new signing key was refused with `no key in the set has that kid` for the life of the process, because the key set files were read once at start. They are now read again on the interval above. The run is `labs/oidc-keycloak`, written up in `docs/live-oidc-run.md`. Against the published 0.6.1 image the exchange, DPoP binding, hostile tokens, revoke, ban, lift, agent credentials, the hand-off and a workload token issued by the provider all pass, and the rotation phase fails with 6 checks passed and 7 failed. Against the change, every phase passes. This is CLAUDE.md invariant 29, held by the gate `scripts/issuer-keys-come-from-the-source.sh` (nothing outside `internal/config` reads the issuer lists) and fourteen scenarios in `features/issuer-keys.feature`, each bound to a test. Twelve planted faults were each caught by a named test.
- **README (#63, #66).** The agent token's door is stated as exercised in TokenFuse. The lines that said no real provider had been used now say what the live run did, and the status list gains the run.
- **Dependency and CI (#64, #62).** `agent-stack-go` moves to v2.0.2, the Go 1.27.3 rebuild, with no API change. The CI actions group is updated.

## Limits

- A provider's opaque `sub` (a UUID in Keycloak) is refused by the exchange, which takes only `user://` or `agent://` subjects. Keycloak can write the URI into `sub`, which the run did. A mapping for other providers is a naming decision, described in `docs/live-oidc-run.md`.

No other commit lies between the 0.6.1 tag and this release.
