# vouchryx 0.9.0

A minor release on 0.8.0. A first hop now refuses an actor credential that is not bound to a key, which is a breaking change for one kind of caller (see Upgrade). The file-mode key set can publish the next signing key ahead of a rotation, so a rotation no longer strands verifiers that have not refreshed yet. The README now names the revoke key variable and the Keyryx custody routes it calls.

## Upgrade

- **Breaking: an actor credential must be bound to a key on a first hop.** A caller that presents an `actor_token` with no `cnf.jkt`, such as a bearer (non-DPoP) provider token naming an agent, is refused with `invalid_grant` and the reason `actor_credential_unbound` in the operator's log. Before 0.9.0 such a token exchanged with any key its holder proved, so a captured copy was a usable credential. Nothing else changes for a caller that already presents a bound actor credential.
  - To keep working, either bind the provider token with DPoP (Keycloak does this per client), or use this service's own `client_credentials` agent credential, which is always bound.
  - The `|unbound` marker on a `VOUCHRYX_TRUSTED_ISSUERS` line does not apply to the actor. It still applies to the subject token only.
- **File mode publishes its key set with `Cache-Control: public, max-age=60`.** A deployment that does not set the new variable sees no other difference.
- **New optional variable `VOUCHRYX_SIGNING_KEYS_PUBLISHED`** (file mode only, refused with `VOUCHRYX_SIGNER=keyryx`). It names a JWK Set file of at most four EC P-256 public keys that are served after the file key and never sign. The file is re-read every `VOUCHRYX_JWKS_RELOAD_SECONDS`, and a file that cannot be used never replaces the set held. The README section "Rotating the file key" gives the three steps: publish the next key, restart onto it with the current key still published, then empty the file.

Rollback is to run the 0.8.0 image again. That image accepts an unbound actor credential again, as it did before this release. It also serves the file key alone in file mode, so finish any rotation that is in its overlap before rolling back.

Pull `ghcr.io/taipanbox/vouchryx:v0.9.0` and restart.

## Changed since 0.8.0

- **Unbound actor credentials refused on a first hop (#76).** The result's key always comes from the actor's verified credential, and an unbound one is refused and logged under the actor's `sub` when it is an `agent://`. `delegation_issued` keeps `cnf_source`, which is now always `actor_token`. The walkthrough in the README still works, because the demo mints a bound agent token.
  - Invariant 31 in CLAUDE.md, three scenarios in `features/delegation.feature`, and eight planted faults, each caught by a named test.
- **Overlap for the file signing key through a published key set (#78).** Ten scenarios in `features/signing.feature`, each bound to a test. The file is read under the same rule as the other key set files, with at most four keys, canonical P-256 coordinates, no private member and a size limit. Invariant 32 in CLAUDE.md and components.json.
- **README: the revoke key and the Keyryx custody routes (#77).** The examples read `VOUCHRYX_REVOKE_KEYS` (a comma-separated list), not the singular name the service never reads. The keyryx-mode paragraph names the custody routes this service calls: `POST /v1/keys/{name}/challenge`, `POST /v1/keys/{name}/delegate` and `GET /v1/jwks/{name}`. `GET /v1/statements/{kid}` is a custody route that this service does not call.
- **agent-stack-go v2.0.3 (#74)**, the Go 1.27.4 rebuild of v2.0.2. Only `go.mod` and `go.sum` change.

No other commit lies between the 0.8.0 tag and this release.
