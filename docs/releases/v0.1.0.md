# vouchryx 0.1.0

The first tagged release, and the first one you can pull instead of build. Until
now every deployment compiled vouchryx from source on the machine it was
installing to; from this tag it is a published image.

It is 0.1.0 rather than 1.0.0 on purpose: `SECURITY.md` supports `main` only and
backports nothing, and the wire is not frozen by a compatibility file the way
the gateway's is. A 1.0 would promise both.

## What is in it

- **RFC 8693 token exchange with nested `act`** on `POST /v1/token`: a subject
  token and an actor token in, a short-lived ES256 JWT out, sender-constrained
  by an RFC 9449 DPoP proof (`cnf.jkt`), so a lifted token is useless without
  the holder's key.
- **Revocation an incident can use** on `POST /v1/revoke`: by one token id, or
  by subject for every token naming that agent anywhere in its chain. `actor`
  and `reason` are required. Enforcement points poll `GET /v1/revocations`,
  which carries `as_of`, so an empty list and an unreachable service are never
  the same answer.
- **Offline verification** from `GET /.well-known/jwks.json`, and RFC 8414
  metadata at `/.well-known/oauth-authorization-server`. There is deliberately
  no introspection endpoint.
- **Cross App Access** (RFC 7523 jwt-bearer with an ID-JAG), closed while
  `VOUCHRYX_CLIENTS` is unset.
- **`vouchryx-demo`**, the shell client that walks the whole loop, in the same
  image.

## The image

`ghcr.io/taipanbox/vouchryx:v0.1.0`, for `linux/amd64` and `linux/arm64`:
static, distroless, non-root (uid 65532), both base images pinned by digest
(`scripts/base-images-pinned-by-digest.sh`). Signed keyless with cosign, with a
build-provenance attestation, and SPDX and CycloneDX SBOMs on this page. It
binds `127.0.0.1:4310` unless `VOUCHRYX_ADDR` says otherwise, and refuses to
start, exit code 2, without `VOUCHRYX_ISSUER`, `VOUCHRYX_SIGNING_KEY` and
`VOUCHRYX_TRUSTED_ISSUERS`. The README's "Install" and "Verify the image"
sections have the commands.

## Measured

On 2026-09-27, a lab image built with the same two-stage shape ran in a
three-node cluster in front of the TokenFuse gateway: an agent's delegation,
revoked by subject mid-run, was refused at the gateway 2.2 seconds later with
the gateway polling the list every second. That run found that a JWKS written
by `vouchryx-demo keygen` names its key `vx-lab` while the service signs with
the key's thumbprint as `kid`, so a gateway must be given the JWKS the service
itself serves; the usage text says so since #32. 208 tests, all green.

## Not proven

The tag-push path of the release workflow (push, signing, attestation, this
page) runs for the first time on this tag. An upstream IdP in the sandbox is
still a demo issuer.
