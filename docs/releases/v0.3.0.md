# vouchryx 0.3.0

A token exchange stops issuing a token for any audience the caller names. The
operator lists the audiences a token may be issued for in
`VOUCHRYX_ALLOWED_AUDIENCES`, and every other request is refused before anything
is signed. The release has two breaking changes, both under Breaking, with what
each one needs in an operator's configuration under Migration.

## Breaking

- **A token exchange for any audience other than `VOUCHRYX_ISSUER` is refused.**
  It answers `400 invalid_target` with no token. Before, the caller's `audience`
  was copied into the token as sent.
- **A trusted issuer with an empty audience stops the service at startup.** A
  line `iss||jwks` in `VOUCHRYX_TRUSTED_ISSUERS` was accepted before, and a token
  from that issuer was then valid for any audience.

## Migration

- **For the first change**, list every audience your callers request in
  `VOUCHRYX_ALLOWED_AUDIENCES`, as comma-separated absolute URLs. Unset keeps the
  issuer as the only audience, which is what a request with no `audience` already
  got. A set list is the whole set: the issuer is not added to it, so include
  `VOUCHRYX_ISSUER` as well if any caller still sends no `audience`.
- **For the second change**, put the audience your identity provider stamps on its
  tokens for this service in the second field of the line
  (`iss|aud|jwks-path`).
- A refused audience is recorded as a `delegation_denied` event with reason
  `audience_not_allowed`, filed under the actor that asked, so an operator can see
  which audience a caller asked for and who asked.
- A deployment whose callers send no `audience` and whose trusted issuers all name
  an audience needs no configuration change to move to this tag.

## Security

- **A token exchange issued a token for whatever `audience` the caller named.** The
  audience is now checked against `VOUCHRYX_ALLOWED_AUDIENCES` before anything is
  signed. The list matches exactly and never by prefix.
- **An empty audience matched every audience.** A trusted issuer configured with
  no audience could vouch for a token minted for any audience. An empty expectation
  now matches nothing, and such a configuration refuses to start.
- **Go 1.27.2.** The toolchain moves from 1.27.0 to 1.27.2, which fixes nine
  standard-library vulnerabilities in `net/http`, its HTTP/2 code, `net/textproto`
  and `crypto/tls` (GO-2026-6603 to GO-2026-6617). The build and the container image
  use it.
- **Audit events are appended under a file lock.** agent-stack-go v1.3.0 takes an
  exclusive lock on each write, so two writers sharing one events file no longer
  append over each other.

## Changed

- **agent-stack-go is pinned at v1.3.0**, from v1.0.2. The library's Go API is
  unchanged, and there is no new dependency.
- **Documentation.** The README's surface table lists `/healthz` and the endpoint
  count, names the stack diagram item, states the required configuration and the
  crypto library pin, and re-measures the revoke coverage it states.
- **Continuous integration.** Every pull request and every push to `main` runs the
  estate secret scan, and the GitHub Actions the workflows use are updated.

## Upgrade notes

- No new route, flag or service. The image tag moves from `v0.2.0` to `v0.3.0`;
  `VOUCHRYX_ALLOWED_AUDIENCES` is the only new variable, and it is optional.

## Not proven

- The audience list is trusted as written. Nothing checks that a listed URL is the
  resource the operator meant.
- Nothing here has been run against a real identity provider, or against a stack
  bring-up with this image.
- The published key set holds one key, so a signing key rotation replaces it at
  once, with no overlap period.
- The DPoP replay cache and the Cross App Access `jti` cache are in memory. A restart
  forgets both.
- The release workflow runs again on this tag. The image, its signature and its
  attestation are checked when that run has finished.
