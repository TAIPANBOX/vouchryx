# vouchryx 0.2.0

The public revocation list stops saying who revoked a token and why. One
change to one public surface; the token exchange, the revoke route and the
store are untouched. This release was approved by the owner.

## Changed (vouchryx#37)

- **`GET /v1/revocations` no longer carries `actor` or `reason`.** The list
  stays public, because verifiers such as the TokenFuse gateway poll it with no
  key, but it now serves a dedicated public entry holding only what a verifier
  needs to refuse a token: `jti`, `subject`, `issued_before` and `expires`,
  beside the list's `as_of`. Before, it served the whole stored entry,
  including the free-text `reason` written by whoever holds a revoke key and
  the `actor` that revoked.
- **The operator's record is unchanged.** `POST /v1/revoke` still requires
  `actor` and `reason`, the store's line format is untouched, and the
  `delegation_revoked` event and the operator log line still carry both. Only
  the public body dropped them.
- An empty list is still `"revocations":[]`, never `null`, so an empty list and
  an unreachable service remain different answers.

## Upgrade notes

- **Behaviour change for anything reading the public list.** A reader that
  looked at `actor` or `reason` in the body gets neither now. The two
  consumers in the stack read exactly `jti`, `subject`, `issued_before`,
  `expires` and `as_of` (TokenFuse's delegation crate, and
  `agent-stack-go/delegation`'s `ParseSnapshot`), and both already ignored the
  other two, so a gateway needs no change. A consumer outside those two was not
  searched for and may exist.
- No new environment variable, route, flag or dependency. A 0.1.0 deployment
  moves to 0.2.0 by moving the image tag; revocations already in the store
  (`VOUCHRYX_REVOCATIONS_PATH`) keep their actor and reason there.
- The README's install and verify lines name `v0.2.0`.

## Not proven

- Not run against TokenFuse's gateway poller or a stack-up or stack-k8s
  bring-up. The Rust check was the delegation crate's own parser and cache
  fed by the live body of a running binary.
- Consumers outside TokenFuse and agent-stack-go were looked for by searching
  the development tree for `v1/revocations`; one outside that tree would not
  have been seen.
- The operator log line and the event stream still contain the reason; that
  is the operator's side and unchanged.
- No authentication was added to the list: anybody who can reach the port
  still learns which `jti` and subjects are revoked, and when their entries
  expire.
- The tag-push path of the release workflow (push, signing, attestation, the
  release page) is proven by v0.1.0, and is not re-run until this tag.
